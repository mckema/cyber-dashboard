Confirmed exploited in the wild

0 entries

CISA adds a CVE to its Known Exploited Vulnerabilities (KEV) catalog only when it has evidence of active exploitation. ENISA's EU Vulnerability Database (EUVD) flags exploited CVEs from a European perspective; a CVE listed by both appears once, with both source labels. US federal agencies get a binding remediation deadline (Fix due, CISA only); for everyone else this is the single best free signal of what to patch first.

If you run any of these at the edge — a VPN concentrator, a firewall, a mail gateway, a support appliance — treat it as an incident, not a patch ticket. Many entries are unauthenticated remote code execution on devices that terminate untrusted traffic, and public exploitation often predates the fix.

Matched to a fairCT component, waiting for triage

0 items

FR-A2 and FR-A3 ask for every new item to be checked against fairCT’s components and for relevant ones to be tracked to a fix. An item is matched when it names a listed component by package, CPE product or vendor and product name, either itself or through the CVE record of one of its CVEs; the rule that matched is shown under the component. A match makes the item a candidate only: affected versions are not checked. Each matched item gets one Linear issue in the Triage inbox, and triage happens in Linear: Accept turns the issue into a ticket with an owner and a due date, listed in the next table; Decline marks the item not relevant, with the reason recorded on the issue. Items that match no component are marked not relevant by rule and get no issue. A row turns red when the item has waited more than one business day; pending means the issue is not created yet.

The seven feeds behind this page

All seven are operated by a government body, an EU agency, a national CERT or a platform, and are free to query without an account. None of them will ever ask you to talk to a sales team.

US Cybersecurity & Infrastructure Security Agency

The authoritative free list of what is actually being exploited. Small, high signal, updated most weekdays. Start every triage cycle here.

Reproduce this from a terminal

These need only curl and jq and work the same on Linux, macOS and Windows (Git Bash). They show raw feed data, not the merged page.

# 1 — CISA KEV entries added in the last 7 days (GitHub mirror of the catalog)
curl -s https://raw.githubusercontent.com/cisagov/kev-data/develop/known_exploited_vulnerabilities.json \
  | jq -r '(now - 7*86400 | strftime("%Y-%m-%d")) as $d
      | .vulnerabilities[] | select(.dateAdded >= $d)
      | [.dateAdded, .cveID, .vendorProject, .product] | @tsv'

# 2 — reviewed critical GitHub advisories, newest first
curl -s "https://api.github.com/advisories?type=reviewed&severity=critical&sort=published&direction=desc&per_page=20" \
  | jq -r '.[] | [.published_at, (.cve_id // .ghsa_id), .vulnerabilities[0].package.ecosystem,
      .vulnerabilities[0].package.name, .vulnerabilities[0].first_patched_version] | @tsv'

# 3 — the ten most recently changed NCSC-NL advisories
curl -s https://advisories.ncsc.nl/csaf/v2/changes.csv | head -n 10

What this list does not cover

NVD scores only part of the CVE stream. Since 15 Apr 2026 NIST enriches (scores and maps to products) only CVEs in CISA KEV and software used by the US federal government. Most new CVEs never get an NVD score, which is why this page takes the score from the CVE record itself. A CVE published without any score does not appear in the critical and high table, so a short table is not an all-clear.

Severity is not risk. CVSS scores the flaw, not your exposure. A 9.8 in a component you do not deploy outranks nothing; a 6.5 on your public login path may outrank everything on this page. The exploited-in-the-wild table is ordered by evidence, which is why it comes first.

Counts move. Every feed backfills, re-scores and occasionally withdraws entries, so two rebuilds minutes apart can disagree. The CVE table shows the highest-scored rows up to a fixed cap; the line above the table says how many are hidden.

CISA KEV can lag. When cisa.gov blocks the job, the catalog is read from CISA’s GitHub mirror, which was about 3 hours behind cisa.gov in a one-day sample (30 Oct 2026). The health table notes when the mirror was used.
